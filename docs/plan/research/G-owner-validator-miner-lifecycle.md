## 1. OWNER lifecycle (ordered checklist with exact chain operations)

### 1.1 Pre-flight reads

1. `SubnetRegistrationRuntimeApi.get_network_registration_cost` (runtime API, `META/api_SubnetRegistrationRuntimeApi.txt`) — surfaced as the `subnet_registration_cost` read (`DOCS/guides/subnets.mdx:17`, `CAT/reads.json` name `subnet_registration_cost`).
2. Price dynamics the owner must budget for: the cost **doubles after each registration by anyone**, decays linearly back over `NetworkLockReductionInterval` = `14 * 7200` = 100,800 blocks (`RT:966`; `DOCS/guides/subnets.mdx:22-24`), floored at `NetworkMinLockCost` = 1,000 TAO (`RT:964` `SubtensorInitialMinLockCost = 1_000_000_000_000`). Network-wide rate limit one registration per `NetworkRateLimit` = 7,200 blocks (`RT:967`; `DOCS/guides/subnets.mdx:27-28`). Under the `pow-faucet` feature (localnet) that rate limit is 0 (`PAL/lib.rs:1022-1026`).
3. The lock is **not refundable**: the entire amount becomes the subnet's initial TAO reserve, alpha reserve sized so the starting price equals the median alpha price across subnets (`DOCS/guides/subnets.mdx:30-34`). The SDK marks this spend `UNBOUNDED` so a `Policy` spend cap blocks it (`SDK/intents/registration.py:223-225`).

### 1.2 Create

4. `SubtensorModule.register_network(hotkey)` (call index 59, coldkey-signed; the `hotkey` becomes `SubnetOwnerHotkey`) — `DOCS/tx/register-subnet.mdx:28-36, 78-87`; call shape `META` `register_network { hotkey: AccountId32 }`. Variant `register_network_with_identity` sets the subnet identity atomically (`META/SubtensorModule_calls.txt:41`; `DOCS/guides/subnets.mdx:36-39`) — no SDK intent, raw call only.
5. **Two completion paths**: if capacity (`SubnetLimit` default 128, `PAL/lib.rs:1454-1456`) is available, `NetworkAdded` fires in the registration block; if full, the extrinsic succeeds with `NetworkRegistrationQueued` and the subnet is only created after the lowest-EMA-price non-immune subnet is dissolved across idle block time (`DOCS/tx/register-subnet.mdx:15-21`; `DOCS/migration.mdx:594-598`). The v11 SDK's `execute` waits for the matching `NetworkAdded` and returns the assigned netuid by default (`SDK/executor.py:803-809, 858-888`, `_complete_subnet_registration` at `SDK/executor.py:343-363`). **rtao must implement the same wait** (event scan for `NetworkAdded` whose owner/hotkey match) and expose `wait_for_registration=false` to return the queue receipt.
6. New-subnet immunity from price-pruning: `NetworkImmunityPeriod` = 1,296,000 blocks (~6 months) (`RT:962`; `DOCS/guides/subnets.mdx:250-251`). If every subnet is immune the registration fails rather than pruning.

### 1.3 Secure the owner account (before or right after create)

7. Recommended layering: owner coldkey = **multisig**; grant an ops key an **`Owner`** proxy (hyperparameters + identity only; cannot transfer or rotate owner); optionally add an announcement delay and monitor `Proxy.Announcements` (`DOCS/guides/subnets.mdx:44-57`; `DOCS/guides/proxies.mdx:354-374`; `DOCS/guides/multisig.mdx:324-345`).
8. Migrating an existing single-coldkey owner to a multisig is an **announced coldkey swap**, not a transfer: `announce_coldkey_swap(new_coldkey)` (0.1 TAO, locks the key), wait `ColdkeySwapAnnouncementDelay` = `prod_or_fast!(5*24*60*60/12, 50)` = 36,000 blocks (`RT:973`), then `swap_coldkey_announced` (`DOCS/guides/multisig.mdx:289-322`; `DOCS/concepts/wallets.mdx:181-208`). Reannouncement delay 7,200 blocks (`RT:974`). Proxy grants and reserved balances do **not** move with the swap (`DOCS/concepts/wallets.mdx:192-199`).
9. Proxy deposits/limits: 0.06 TAO base + 0.033 TAO per delegation, max 20 proxies; announcements 0.036 + 0.068 each, max 75 (`DOCS/guides/proxies.mdx:376-384`). Multisig deposit 0.132 TAO + 0.032 per threshold unit, max 100 signatories (`DOCS/guides/multisig.mdx:416-423`).
10. Proxy type allowlists are deny-by-default; `Owner` is limited to owner-settable subnet configuration and identity, not owner-key rotation; `NonCritical` cannot call `root_dissolve_network`; `Staking` cannot wrap `Utility.batch_all` (`DOCS/migration.mdx:534-543`; `DOCS/guides/proxies.mdx:47-71`).

### 1.4 Activate

11. Read `subnet_start_schedule` (storage `NetworkRegisteredAt` + constant `InitialStartCallDelay`) — `DOCS/query/subnet-start-schedule.mdx:7-9, 45-47`. The runtime currently sets `InitialStartCallDelay: u64 = 0` (`RT:979`), i.e. `start_call` is immediately callable on this runtime; the storage item `StartCallDelay` is root-settable (`AdminUtils.sudo_set_start_call_delay`, `META/AdminUtils_calls.txt`), so rtao must read it, never hardcode.
12. `SubtensorModule.start_call(netuid)` (call index 92, owner-only, once): `do_start_call` requires `FirstEmissionBlockNumber` unset, `current >= NetworkRegisteredAt + StartCallDelay`, then sets `FirstEmissionBlockNumber = current+1` and `SubtokenEnabled = true`, emitting `FirstEmissionBlockNumberSet` (`PAL/subnets/subnet.rs:547-572`; `DOCS/tx/start-call.mdx:8-19, 66-79`). Before this flag: all staking paths fail with `SubtokenDisabled`, no emissions, and `set_children` applies immediately without the pending cooldown (`DOCS/hyperparameters/subnet-is-active.mdx:26-44`).
13. **Two independent "on" flags**: `subnet_is_active` (owner's `start_call`, storage `SubtokenEnabled`) and `subnet_emission_enabled` (root-only `AdminUtils.sudo_set_subnet_emission_enabled`, wrapped in `Sudo.sudo`; new subnets start `false`). A subnet can run epochs and trade alpha while receiving zero pool-side TAO injection (`DOCS/guides/subnets.mdx:86-106`; `DOCS/hyperparameters/subnet-emission-enabled.mdx:6-33`; `DOCS/tx/set-subnet-emission-enabled.mdx:8-27`). An owner dashboard must surface both.

### 1.5 Hyperparameter tuning

14. Entry point: `AdminUtils.sudo_set_*` calls with origin = owner-or-root; the SDK's `SetHyperparameter(netuid, name, value)` maps names to setters (`SDK/intents/hyperparameters.py:31-66`). Owner-settable names (exact list): `epoch_consensus, tempo, immunity_period, min_allowed_weights, weights_version, activity_cutoff_factor, min_burn, max_burn, bonds_moving_avg, bonds_penalty, serving_rate_limit, commit_reveal_period, max_allowed_uids, burn_increase_mult, burn_half_life, collateral_lock_share, collateral_drain_ratio, adjustment_alpha, rho, max_difficulty, alpha_sigmoid_steepness, min_childkey_take, owner_immune_neuron_limit, alpha_low, alpha_high, commit_reveal_weights_enabled, liquid_alpha_enabled, registration_allowed, network_pow_registration_allowed, yuma3_enabled, bonds_reset_enabled, transfers_enabled, owner_cut_enabled, owner_cut_auto_lock_enabled` (`SDK/intents/hyperparameters.py:31-66`; the generated tx page lists the same AdminUtils setters, `DOCS/tx/set-hyperparameter.mdx:22-29`).
15. **Units** (`SDK/hyperparams.py:55-77, 110-408`; `DOCS/hyperparameters/index.mdx:10-59`): `u16` fraction (65535 = 1.0: kappa, max_weights_limit, alpha_low/high, bonds_penalty, min_childkey_take, collateral_lock_share); `u64` fraction (adjustment_alpha); `per_million` (bonds_moving_avg; 900000 = 0.9); `rao` (min_burn, max_burn); `blocks` (immunity_period, tempo, weights_rate_limit, serving_rate_limit, burn_half_life, activity_cutoff); `epochs` (commit_reveal_period); `difficulty` (u64; u64::MAX = disabled); `fixed128` U64F64 (burn_increase_mult, collateral_drain_ratio; bits/2^64 = real value, encoded on the wire as a one-field struct `{bits}` — `SDK/intents/hyperparameters.py:145-147`); `int`; `bool`. Value convention rtao should mirror: a plain integer is the raw on-chain value, a value with a decimal point is the human form (`SDK/hyperparams.py:10-13, 711-769`). `alpha_low`/`alpha_high` share `sudo_set_alpha_values(netuid, low, high)`: read `AlphaValues` and keep the other side (`SDK/intents/hyperparameters.py:138-143`). `epoch_consensus` takes the enum `Yuma|Null` as `{"mode": ...}` (`SDK/intents/hyperparameters.py:126-137`).
16. **Bounds/defaults an owner must respect**:
    - `tempo`: owner bounded `MIN_TEMPO`=360 … `MAX_TEMPO`=50,400 (`PAL/lib.rs:2325-2327`), rate-limited once per 360 blocks, change re-anchors `LastEpochBlock` so the next epoch is a full tempo away (`DOCS/hyperparameters/tempo.mdx:26-29, 52-58`). Default `INITIAL_SUBNET_TEMPO = prod_or_fast!(360, 10)` (`RT:904`).
    - `activity_cutoff_factor` (per-mille of tempo): bounds 1,000…50,000, default 13,889 (`PAL/lib.rs:2329-2334`); effective cutoff = factor×tempo/1000 (`DOCS/hyperparameters/activity-cutoff-factor.mdx:14-25`). The absolute `activity_cutoff` is legacy/derived and the `SubtensorModule.set_tempo` (idx 139) / `set_activity_cutoff_factor` (idx 140) calls are deprecated no-ops that still charge a fee (`DOCS/migration.mdx:599-607`) — they are still present in metadata (`META/SubtensorModule_calls.txt:54, 66`); **rtao must never emit them**.
    - `immunity_period`: default 4,096 blocks (`RT:928`); must exceed `commit_reveal_period × tempo` or new miners can be pruned before first reveal (`DOCS/guides/validating.mdx:186-188`).
    - `max_allowed_uids`: floor `MinAllowedUids` = 64 (`RT:963`), default 256 (`RT:916`); budget `floor(256/mechanism_count)` for Yuma and `floor(2500/mechanism_count)` for Null (`DOCS/guides/null-consensus.mdx:43-50`; `SDK/hyperparams.py:316-322`); lowering below current N is rejected (`DOCS/hyperparameters/max-allowed-uids.mdx:12`). **Doc discrepancy**: `DOCS/hyperparameters/max-allowed-uids.mdx:12` says `floor(16000/mechanism_count)` for Null while the guide and SDK say 2,500 — read `SubtensorModule` constants/`MinAllowedUids` live rather than trusting either page.
    - `weights_version` (`WeightsVersionKey`, u64): owner may change at most once per `WeightsVersionKeyRateLimit` = 5 tempos (`PAL/lib.rs:1044-1046`; `DOCS/hyperparameters/weights-version.mdx:36-37`); checked also at reveal time, so a bump invalidates in-flight commits (`weights-version.mdx:27-29`).
    - `min_burn`/`max_burn`: runtime defaults 500,000 rao / 100 TAO (`RT:945, 948`); `MinBurnUpperBound` 1 TAO, `MaxBurnLowerBound` 0.1 TAO (`RT:949-950`). `burn_half_life` default 360 blocks, `burn_increase_mult` default 1.26 U64F64 (`PAL/lib.rs:677-685`), mult bounded 1..3 by the SDK (`SDK/hyperparams.py:330-331`).
    - `collateral_lock_share` ≤ 62258 (95%); `collateral_drain_ratio` in (0, 10] (`SDK/hyperparams.py:338-354`; `DOCS/guides/mining/collateral.mdx:465-469`). Both snapshot per miner at registration; changes are prospective only (`collateral.mdx:462-464`).
    - `owner_immune_neuron_limit`: 1..10, default 1 (`PAL/lib.rs:2810-2812`; `DOCS/hyperparameters/owner-immune-neuron-limit.mdx:12`).
    - `registration_allowed` / `network_pow_registration_allowed`: independent toggles; at least one must stay enabled on a non-root subnet (`DOCS/hyperparameters/registration-allowed.mdx:6-9`). PoW default off (`DOCS/hyperparameters/network-pow-registration-allowed.mdx:6-9`).
    - `commit_reveal_period` (`RevealPeriodEpochs`): 1..100 epochs, default 1 (`DOCS/hyperparameters/commit-reveal-period.mdx:27-29`; `PAL/lib.rs:1219-1221`). `commit_reveal_weights_enabled` default **true** (`PAL/lib.rs:1308-1310`).
    - `bonds_moving_avg` default 900,000; `bonds_penalty` default u16::MAX; `alpha_low/high` defaults 45875/58982 (0.7/0.9); `liquid_alpha_enabled` only effective with `yuma3_enabled` (`RT:932-933, 969-972`; `DOCS/guides/validating.mdx:224-229`).
17. **Two chain-side gates on every owner admin call** (`DOCS/guides/subnets.mdx:188-196`): per-parameter rate limit `OwnerHyperparamRateLimit` default 2 tempos (`PAL/lib.rs:1442-1444`), and the admin freeze window `AdminFreezeWindow` default 10 blocks before epoch end (`PAL/lib.rs:1436-1438`), enforced via `ensure_sn_owner_or_root_with_limits` + `ensure_admin_window_open` (visible in `sudo_set_mechanism_count`, `DOCS/tx/set-mechanism-count.mdx:71-98`). rtao's owner tooling should compute "next safe block" from `epoch_status` before submitting.
18. **Root-only** (not reachable through the owner intent): `kappa` (32,767 ≈ 0.5), `max_validators` (`MaxAllowedValidators` 128), `weights_rate_limit` (`WeightsSetRateLimit` 100), `max_weights_limit`, `min_difficulty`, `difficulty`, `activity_cutoff`, `adjustment_interval`, `target_regs_per_interval`, `max_regs_per_block`, `yuma_version`, `subnet_is_active`, `subnet_emission_enabled`, `user_liquidity_enabled` (`DOCS/hyperparameters/index.mdx:14-55`; `DOCS/guides/subnets.mdx:198-202`). Also root-only in `AdminUtils`: `sudo_set_recycle_or_burn`, `sudo_set_sn_owner_hotkey` (owner-or-root per `PAL/subnets/subnet.rs:574-577`), `sudo_set_liquid_alpha_consensus_mode` (owner within window per `DOCS/migration.mdx:610-615`), `sudo_set_mechanism_emission_split`, `sudo_set_subtoken_enabled`, `sudo_set_start_call_delay` (`META/AdminUtils_calls.txt`).

### 1.6 Owner hotkey, immunity, and the "don't mine on the owner key" rule

19. `SubnetOwnerHotkey` is set at `register_network(hotkey)` and rotated with `AdminUtils.sudo_set_sn_owner_hotkey` (owner-or-root per the pallet doc comment at `PAL/subnets/subnet.rs:574-577`; it has its own `TransactionType::SetSNOwnerHotkey` rate-limit slot, `PAL/utils/rate_limiting.rs:143`; call listed in `META/AdminUtils_calls.txt`).
20. The owner UID always receives a validator permit and is exempt from `StakeThreshold` (`DOCS/guides/validating.mdx:54-55`; `DOCS/hyperparameters/max-validators.mdx:18`); owner hotkeys are permanently prune-immune up to `ImmuneOwnerUidsLimit` (`DOCS/hyperparameters/owner-immune-neuron-limit.mdx:10`). Recommended habit: run a validator on the owner hotkey (owner cut + dividends land on one key) but **never mine** on it — miner incentive directed at owner-associated hotkeys is burned or recycled per `RecycleOrBurn`, and the withheld fraction (`MinerBurned`) also scales the subnet's cross-subnet emission share down (`DOCS/guides/subnets.mdx:130-133`; `DOCS/guides/mining/index.mdx:50-53`; `DOCS/concepts/emissions.mdx:81-92`).

### 1.7 Emission split, mechanisms, Null consensus

21. Per-tempo alpha split: 18% owner (`SubnetOwnerCut` 11796/65535, `RT:965`), ~41% miners, ~41% validators+stakers (`DOCS/concepts/emissions.mdx:146-152`). `owner_cut_enabled` toggles the cut, `owner_cut_auto_lock_enabled` auto-locks it into conviction (`DOCS/guides/subnets.mdx:121-125, 169`).
22. Mechanisms: `AdminUtils.sudo_set_mechanism_count(netuid, mechanism_count)` (owner, rate-limited once per 7,200 blocks, blocked in freeze window); cap `MaxMechanismCount` = 2 (`PAL/lib.rs:3558-3560`); emission split is a u16 vector summing to 65,535 set by root (`sudo_set_mechanism_emission_split`), count change resets to even; `max_allowed_uids × count ≤ 256` (`DOCS/guides/subnets.mdx:219-242`; `DOCS/tx/set-mechanism-count.mdx:8-15`). Storage for per-mechanism items (`Weights`, `LastUpdate`, …) is keyed by `mechid * 4096 + netuid` (`SDK/intents/weights.py:165-167`, `GLOBAL_MAX_SUBNET_COUNT = 4096` at `SDK/settings.py:31`); the metagraph runtime record's `netuid` field carries that storage index so `mechid = netuid_field // 4096` (`SDK/metagraph.py:384`). Mechanism-count changes in Null require commit queues to drain (`DOCS/guides/null-consensus.mdx:109-116`).
23. Null consensus (`epoch_consensus = Null`): one permit holder (highest unrounded stake weight) sets weights; dividends proportional to all positive stake; no bonds; capacity `floor(2500/mechanism_count)`; owner switch back to Yuma requires population to fit; ciphertext limit `floor(32 KiB/mechanism_count)` vs Yuma's 5,000 bytes; shared queue 64 KiB / 64 commits per subnet epoch; `raw_u16` weights path (`DOCS/guides/null-consensus.mdx:6-33, 37-57, 148-182`). Trimming in Null uses `AdminUtils.sudo_trim_null_uids_batch` (≤64 UIDs per tx, resumable workflow with a local recovery record) (`null-consensus.mdx:59-107`).
24. Owner can trigger an early epoch: `SubtensorModule.trigger_epoch` (`META/SubtensorModule_calls.txt:86`; `DOCS/concepts/emissions.mdx:178-179`); `PendingEpochAt` is surfaced by `epoch_status` (`SDK/reads/epochs.py:90-128`). At most `MaxEpochsPerBlock` = `prod_or_fast!(2, 32)` epochs run per block (`RT:987`).

### 1.8 UID capacity management

25. `AdminUtils.sudo_trim_to_max_allowed_uids(netuid, max_n)` (call index 78): once per 216,000 blocks (~30 days), `max_n ≥ 64`, immune UIDs ≤ `MaxImmuneUidsPercentage` 80% of new max (`RT:983`), survivors renumbered from 0, trimmed state deleted (`DOCS/tx/trim-subnet.mdx:8-20`; `DOCS/guides/subnets.mdx:204-217`). Raising `max_allowed_uids` is a plain hyperparameter set.
26. Pruning preference: lowest emission non-immune, ties → older registration, then lower UID; if pruning would leave ≤ `MinNonImmuneUids` (default 10, `PAL/lib.rs:1460-1462`) non-immune UIDs, the lowest-emission immune neuron is pruned instead (`DOCS/hyperparameters/immunity-period.mdx:10-12`).

### 1.10 Collateral, conviction, leasing, crowdloan, dissolve

29. Collateral policy (owner): `collateral_lock_share` p and `collateral_drain_ratio` k; registration charges `burned = (1−p)·T`, `locked = max(0, p·T − standing)`; release per tempo `min(locked − min_locked, k × emission)`; no withdrawal path; survives deregistration; events `CollateralLocked`, `MinCollateralSet`, `CollateralLockShareSet`, `CollateralDrainRatioSet` (`DOCS/guides/mining/collateral.mdx:23-82, 471-519`). Recommended presets in `collateral.mdx:446-460`.
30. Conviction/ownership transfer: after each epoch, if subnet age ≥ 2,629,800 blocks and the top hotkey's own conviction > 18% of `SubnetAlphaOut − SubnetProtocolAlpha − AlphaBurned` (saturating), `SubnetOwnerHotkey`/`SubnetOwner` change (`DOCS/guides/conviction.mdx:76-97`; `DOCS/migration.mdx:521-526`). `MaturityRate` 311,622 and `UnlockRate` 934,866 blocks are governance storage, read live (`conviction.mdx:64-66`). Owner-hotkey locks mature instantly (`conviction.mdx:70-74`). Owner dashboards: `subnet_convictions`, `hotkey_conviction`, `coldkey_lock`, `most_convicted_hotkey` reads (`CAT/reads.json`).
31. Leasing/crowdloan: `create_crowdloan` … `register_leased_network(emissions_share, end_block?)` (idx 110, must be dispatched in a crowdloan context); `emissions_share` is a percent **of the owner cut**; contributor dividends paid every `LeaseDividendsDistributionInterval` = 100 blocks (`RT:982`); crowdloans run 50,400–432,000 blocks; refunds ≤ 50 contributors per `refund_crowdloan`; `terminate_lease` after `end_block` (`DOCS/guides/subnets.mdx:283-311`; `DOCS/tx/register-leased-network.mdx:8-29`). The lease owner is a chain-created account with a `SubnetLeaseBeneficiary` proxy for the beneficiary (`DOCS/guides/subnets.mdx:59-62`).
32. Dissolution: `dissolve_network` / `root_dissolve_network` exist (`META/SubtensorModule_calls.txt:28, 48`); scheduled over `DissolveNetworkScheduleDuration` 5 days (`RT:975`). Payout is pro-rata over all alpha to coldkey free balance; protocol-held alpha dilutes; conviction locks deleted; multi-block settlement cursor retries unpaid hotkeys (`DOCS/guides/subnets.mdx:260-269`; `DOCS/migration.mdx:638-643`).

## 2. VALIDATOR lifecycle

### 2.1 Registration (burn vs PoW vs root)

1. **Burn**: `SubtensorModule.burned_register(netuid, hotkey)` (idx 7, coldkey-signed) pays `Burn[netuid]`; with `CollateralLockShare` p>0 the p-share is staked+locked on the hotkey (`DOCS/tx/burned-register.mdx:8-24, 74-88`). The SDK forces MEV-shielded submission for this intent (`mev_shield_required = True`, `SDK/intents/registration.py:137-141`) because the collateral top-up is an AMM buy under a 5% runtime bound (`DOCS/guides/mining/collateral.mdx:113-118`). Price dynamics: halves every `burn_half_life` (360) blocks, ×`burn_increase_mult` (1.26) per registration, clamped [`min_burn`, `max_burn`] (`DOCS/guides/mining/burn.mdx:20-35`). `MaxRegistrationsPerBlock` default 1 (`RT:930`). The legacy `register` call retains burn behaviour (`DOCS/hyperparameters/registration-allowed.mdx:12-15`).
2. **PoW**: `SubtensorModule.pow_register(netuid, work_block, nonce, work: [u8;32], hotkey)` (idx 152, `Pays::No`, coldkey-signed; `DOCS/tx/pow-register.mdx:78-96`). Challenge prefix = `b"subtensor-pow-register-v1" ‖ netuid LE u16 ‖ block_hash(32) ‖ hotkey(32) ‖ coldkey(32)`; seal = `keccak(sha256(prefix ‖ nonce LE u64))`; accepted when `LE(seal) ≤ (2^256−1)/difficulty`; proof valid for `MAX_WORK_AGE_BLOCKS` = 5 blocks; challenge refreshed every 12 s; `LastPowRegistrationBlock[hotkey]` prevents reuse; `RegistrationsThisBlock < MaxRegistrationsPerBlock` (`SDK/pow_registration.py:18-36, 85-105, 122-253`). Difficulty = clamp(`Difficulty`, `MinDifficulty`(root), `MaxDifficulty`(owner)) (`pow_registration.py:39-43`); bumps only difficulty (`DOCS/guides/null-consensus.mdx:120-131`). Mining uses only public data (GPU via OpenCL in `bittensor-core`, CPU fallback) — rtao can port `CORE/pow`.
3. **Root**: `SubtensorModule.root_register(hotkey)` (idx 62): burn-based, 64 seats, evicts lowest-staked non-immune member, capped per block and per interval (3× `target_registrations_per_interval`), auto-childkeys the hotkey at full proportion to every subnet owner unless `set_auto_parent_delegation_enabled(false)` was called first (`DOCS/tx/root-register.mdx:8-24`; `DOCS/guides/root-reborn.mdx:106-148`). Root validators are "fund managers" (baskets, `swap_basket`, `claim_root_with_hotkey`) — `DOCS/guides/root-reborn.mdx:47-104, 150-197`.
4. Registration is continuous (no windows); confirm with `uid`/`netuids_for_hotkey` reads (`DOCS/guides/mining/index.mdx:73-84`). Event: `NeuronRegistered`.

### 2.2 Stake, permit, threshold

5. Stake weight = `alpha_stake + tao_stake × TaoWeight`; `TaoWeight` runtime default `971_718_665_099_567_868` (~5.27% of u64::MAX, `RT:976`) but the docs state mainnet governance set 0.18 (`DOCS/guides/validating.mdx:49-52`; `DOCS/concepts/emissions.mdx:201-204`) — read `SubtensorModule.TaoWeight` live.
6. Permits recomputed each epoch: top-K by stake weight, K = `MaxAllowedValidators` (128, `RT:922`; `PAL/epoch/run_epoch.rs:322` `is_topk_nonzero`); `StakeThreshold` (storage, runtime default 0 at `PAL/lib.rs:1213-1215`; mainnet "around 1,000 TAO-equivalent", `validating.mdx:44-47`) zeroes stake below it and is the minimum to set weights (`NotEnoughStakeToSetWeights`, `PAL/subnets/weights.rs:1016`; `run_epoch.rs:287`). Losing a permit stops dividends and **deletes bonds** (`validating.mdx:57-63`; `DOCS/hyperparameters/max-validators.mdx:21-29`). Activity cutoff masks validators whose `LastUpdate + cutoff < current_block` (`run_epoch.rs:229-239`). Practical bar: community rule of thumb ~20k TAO-equivalent (`validating.mdx:30-35`).
7. Take: default 18% (11796/65535, `RT:935`); `increase_take`/`decrease_take(hotkey, take: PerU16)` (idx 66/65, **`Pays::Yes`**, `DOCS/tx/set-take.mdx:66-98`); increases rate-limited `TxDelegateTakeRateLimit` = 216,000 blocks (`RT:958`); `MinDelegateTake` 0. SDK `SetTake` reads current take and dispatches the right direction (`DOCS/tx/set-take.mdx:8-15`). Note the conflict: `DOCS/concepts/transactions.mdx:161-165` says take changes are fee-free; the dispatch annotations and `DOCS/migration.mdx:569-570` say `Pays::Yes` — trust the dispatch.
8. Childkeys: `set_children(hotkey, netuid, children: Vec<(u64, AccountId32)>)` (idx 67, coldkey, proportion = share of u64::MAX, ≤5 children (`PAL/staking/set_children.rs:39-41`), rate limit 150 blocks per hotkey per subnet (`PAL/utils/rate_limiting.rs:27`), applied after `PendingChildKeyCooldown` = `prod_or_fast!(7_200, 15)` (`PAL/lib.rs:1356-1357`, `set_children.rs:589`) except on not-yet-started subnets; parent needs `StakeThreshold` unless owner hotkey (`DOCS/tx/set-children.mdx:8-25`). `set_childkey_take` 0..18% (`RT:937-939`), increases rate-limited `INITIAL_CHILDKEY_TAKE_RATELIMIT = prod_or_fast!(216000, 5)` (`RT:907`). Reads: `children`, `parents`, `pending_children`. Bootstrapping a new subnet usually means asking a root validator to childkey your validator (`DOCS/guides/subnets.mdx:313-320`).
9. Identity to attract delegation: `set_identity` (`validating.mdx:17-22`). Hotkey rotation: `swap_hotkey(hotkey, new_hotkey, netuid: Option)` (0.1 TAO all-subnets / 0.001 TAO per-subnet, `KeySwapCost` `RT:968`, `KeySwapOnSubnetCost` `RT:980`, per-(subnet,coldkey) cooldown `HotkeySwapOnSubnetInterval` = `prod_or_fast!(7200, 1)` `RT:981`); `swap_hotkey_v2` with `keep_stake` (`DOCS/tx/swap-hotkey.mdx:8-22`).

### 2.3 Serving requirements

### 2.4 Metagraph sync cadence

11. One call: `SubnetInfoRuntimeApi.get_metagraph(netuid)` → `Option<Metagraph>` with per-UID vectors (`hotkeys, coldkeys, identities, axons, active, validator_permit, last_update, block_at_registration, rank, trust, consensus, incentives, dividends, pruning_score, emission, alpha_stake, tao_stake, total_stake, collateral_*`) plus subnet fields (`META` get_metagraph output lines 212-328 of the saved dump; typed shape in `SDK/metagraph.py:127-235, 297-403`). Pin multi-read computations to one block (`client.at(block)` snapshot, `DOCS/concepts/client.mdx:135-146`).
12. Cadences seen in the wild: SN2 validator resyncs **hourly** and refreshes miner connections every 60 s (`SN2/.../maintenance.rs:52-56, 73-76`); legacy template resyncs when `block − last_update[uid] > epoch_length` (default 100 blocks) (`TPL/template/base/neuron.py:147-153`, `TPL/template/utils/config.py:84-89`); Chi syncs every 12 s loop (`CHI/validator.py:96-136`); SN1 syncs at every weight-loop iteration with `lite=False` (`SN1/src/validator/src/validator/validator.py:91`). SN2 also forces an RPC reconnect after 3 consecutive sync failures (`maintenance.rs:359-393`; `METAGRAPH_FAILURE_RECONNECT_THRESHOLD`, `validator_loop/mod.rs:213`).
13. On resync, reset per-UID state when the hotkey at a UID changed (template zeroes scores, `TPL/template/base/validator.py:303-317`; SN2 resets performance and score, `maintenance.rs:436-452`). Collateral guide insists scoring be keyed by **hotkey root** (`HotkeyRoot`/`HotkeySuccessor` lineage) not UID (`DOCS/guides/mining/collateral.mdx:249-259`).

### 2.6 Weight normalization and submission rules (exact)

16. Chain calls: `set_mechanism_weights(netuid, mecid: u8, dests: Vec<u16>, weights: Vec<u16>, version_key: u64)` (idx 119, `Pays::No`; rejected with `CommitRevealEnabled` when CR is on) and `commit_timelocked_mechanism_weights(netuid, mecid, commit: BoundedVec<u8, 32 KiB>, reveal_round: u64, commit_reveal_version: u16)` (idx 118, `Pays::No`) (`DOCS/tx/set-weights.mdx:78-127`; `META` call shapes). Legacy `set_weights` (line 67), `commit_timelocked_weights` (23), salt-based `commit_weights`/`reveal_weights` (24, 47), `batch_*` (12-14), `commit_crv3_mechanism_weights` (20) and `commit_mechanism_weights`/`reveal_mechanism_weights` (21, 46) all still exist in `META/SubtensorModule_calls.txt`, next to the current `set_mechanism_weights` (60) and `commit_timelocked_mechanism_weights` (22); SN2 still uses `commit_timelocked_weights` (`SN2/sn2-chain/src/weights.rs:93-102`). **Recommendation**: rtao emits the `*_mechanism_*` variants with `mecid = 0` by default, matching the v11 SDK (`SDK/intents/weights.py:373-376`).
17. Client-side conformance (canonical, `SDK/intents/weights.py`): accept `{uid: weight}` or parallel lists, reject duplicates/negatives/non-finite (`:54-67, 117-141`); if `MaxWeightsLimit < 65535` and not a pure self-weight, clip so no normalized element exceeds `limit` by cutoff search redistributing mass (`:83-114`); then **max-upscale** (`round(w/max × 65535)`) and drop zeros (`:69-80`); enforce `len ≥ MinAllowedWeights` after dropping zeros, self-weight exempt (`:252-257`). Chain-side: `check_length` uses `min(min_allowed_weights, SubnetworkN)` (`DOCS/hyperparameters/min-allowed-weights.mdx:14-22`); `max_weight_limited` checks `max/sum ≤ limit/65535` after max-upscale but the runtime's `get_max_weight_limit` is pinned to `u16::MAX` so it always passes (`DOCS/hyperparameters/max-weights-limit.mdx:11-35`); `check_version_key` passes when stored key is 0 or submitted ≥ stored (`weights-version.mdx:13-22`; `PAL/subnets/weights.rs:1285`); `check_rate_limit` passes when `current − LastUpdate[uid] ≥ WeightsSetRateLimit` (never-submitted passes) (`DOCS/hyperparameters/weights-rate-limit.mdx:13-18`; `PAL/subnets/weights.rs:1295`); `check_validator_permit` (`weights.rs:1350`); stake ≥ `StakeThreshold` (`weights.rs:1016`). Null `raw_u16` mode submits integers in 0..65535 without scaling and requires Null mode (`SDK/intents/weights.py:228-243, 261-265`; `DOCS/guides/null-consensus.mdx:148-170`).
18. Preflight the SDK does before signing (rtao should match): read at one block `Uids[netuid,hotkey]`, `CommitRevealWeightsEnabled`, `WeightsSetRateLimit`, `LastUpdate[mechid*4096+netuid]`, `MinAllowedWeights`, `MaxWeightsLimit`, `SubnetEpochConsensus`; fail with `NOT_REGISTERED`, `RATE_LIMITED` (with blocks/seconds remaining), or `NOT_AUTHORIZED` (Null and not the sole permit holder) (`SDK/intents/weights.py:154-215`). Not preflighted: stake threshold, Yuma permit, version key (`:159-161`).
19. **Rate limit vs commit-reveal**: with CR on, the 100-block limit (`DefaultWeightsSetRateLimit`, `PAL/lib.rs:1088-1090`) applies to the **commit** (`CommittingWeightsTooFast`) and `LastUpdate` is bumped at commit time, so `blocks_since_last_update` is the health signal (`DOCS/hyperparameters/weights-rate-limit.mdx:20-33`; `SDK/reads/epochs.py:69-75`). Rate limits arm only on **successful** ops (`DOCS/concepts/transactions.mdx:171-174`). At most 10 unrevealed commits per hotkey (`PAL/subnets/weights.rs:211`).
20. **Timelocked commit construction** (port `CORE/timelock`): read at one block `Tempo, RevealPeriodEpochs, LastEpochBlock, PendingEpochAt, SubnetEpochIndex, BlocksSinceLastStep` plus detected block time, build `EpochScheduleState` (`CORE/timelock/epoch_schedule.rs:17-24`), `predict_first_reveal_block` simulates the chain's `block_step` pipeline (`epoch_schedule.rs:108-128`), target ingest block = reveal block + `SECURITY_BLOCK_OFFSET` 3, convert to wall-clock via block time, `reveal_round = floor((target_secs − GENESIS_TIME 1692803367)/DRAND_PERIOD 3)`, payload `WeightsTlockPayload { hotkey, uids, values, version_key }` SCALE-encoded, encrypted to drand quicknet (pubkey/chain hash in `CORE/timelock/constants.rs`) and compressed (`CORE/timelock/mod.rs:160-200`; `SDK/intents/weights.py:268-333`). `commit_reveal_version` default 4 (`SDK/intents/weights.py:33`; SN2 `COMMIT_REVEAL_VERSION 4`, `SN2/sn2-chain/src/weights.rs:18`). Ciphertext bound: `MAX_CRV3_COMMIT_SIZE_BYTES = 32*1024` (`PAL/lib.rs:63`), Yuma effectively 5,000 bytes (`DOCS/guides/null-consensus.mdx:181`). The reveal round math depends on real block time (0.25 s on fast-blocks localnets) — read `block_time`/`is_fast_blocks` (`SDK/intents/weights.py:318-322`). SN2's `bittensor_drand::generate_commit(uids, values, version_key, tempo, current_block, netuid, reveal_period, 12.0, hotkey)` is the older v1 formula (`SN2/sn2-chain/src/weights.rs:60-82`); rtao should implement the v2 stateful one because the epoch schedule is stateful (owner-triggered epochs, tempo changes) (`SDK/reads/epochs.py:19-28`).
21. Cadence conventions: SN2 polls every 60 s and submits when `blocks_since_last_update ≥ 100`, holds previous weights if every miner weight is zero (owner-only row would burn the epoch), gives the owner UID 0.8 of the row (`SN2/.../maintenance.rs:508-677`; `SN2/sn2-types/src/constants.rs:9-10`; `SN2/sn2-validator/src/scoring.rs:125-172`); template every `epoch_length` 100 blocks with `version_key = spec_version` (`TPL/template/base/validator.py:222-284`; `TPL/template/__init__.py:22-28` = `1000*major + 10*minor + patch`); Chi once per tempo (`CHI/validator.py:105-128`); SN1 every `WEIGHT_SUBMIT_INTERVAL`, falling back to the stake-weighted average of on-chain validator rows when its orchestrator is down (`SN1/.../validator.py:120-142, 332-352`). The docs' guidance: scores on chain are stale by the reveal period; `epoch_status`, `blocks_since_last_update`, `reveal_period`, `weights_rate_limit` are the timing reads (`DOCS/guides/validating.mdx:149-152, 189-192`). v11 `version_key` defaults to **0**, not the SDK version (`DOCS/migration.mdx:400-404`).
22. Submission robustness: SN2 bounds submit (30 s) and finalization (180 s), and if the watch is lost it reconciles by polling `LastUpdate[uid]` for 60 s at 6 s intervals (`SN2/sn2-chain/src/weights.rs:14-17, 104-180`). The SDK's one-call `bt.set_weights` retries transient pool rejections twice and raises on failure (`SDK/_subtensor.py:167-205`); `execute` retries only on transient pool errors, never dispatch errors (`SDK/executor.py:795-800, 830-841`). Hotkey-signed calls are fee-free (`Pays::No`) and the SDK refuses to MEV-shield them (`DOCS/concepts/advanced.mdx:146-150`).
23. Reading back: `weights` read returns rows normalized to fractions; `bonds` likewise; `timelocked_weight_commits` lists pending ciphertexts with `reveal_round`/`reveals_at` (`DOCS/query/weights.mdx:8-12`; `DOCS/query/timelocked-weight-commits.mdx:8-12`).

### 2.7 Collateral enforcement (validator side)

24. Validators enforce collateral off-chain: read `collateral_locked`/`collateral_min`/`collateral_earned` from the metagraph (spec ≥ 435) or `subnet_collateral` (includes dormant bonds with `uid: None`, `headroom_alpha`, `shortfall_alpha`, `releasable_work_alpha`) and simply zero-score under-collateralized or misbehaving hotkeys; there is no slash extrinsic (`DOCS/guides/validating.mdx:208-214`; `DOCS/guides/mining/collateral.mdx:228-259, 352-381`; `DOCS/query/subnet-collateral.mdx:8-12`).

### 2.8 Auto-update conventions

25. SN2 (Rust): background task checks GitHub latest release every 300 s, downloads `<binary>-<platform>` + `SHA256SUMS`, verifies sha256 and a GitHub/Sigstore attestation, atomically replaces the executable, then signals graceful shutdown via a `watch` channel for the supervisor to restart; gated on `SN2_RELEASE_CHANNEL == "mainnet"` and `--no-auto-update` (`SN2/sn2-chain/src/auto_update.rs:8-15, 47-183, 197-232`; `SN2/sn2-validator/src/main.rs:62-67`). ## 3. MINER lifecycle

### 3.1 Scope and register

1. Reads before paying: `burn` (current price), `subnet_hyperparameters`, `collateral_policy`, `metagraph`, `immunity_period` (`DOCS/guides/mining/index.mdx:28-48`). Register with `burned_register` (or `pow_register` when the owner enabled PoW) exactly as in §2.1; the UID goes to the wallet hotkey unless `hotkey_ss58` given (`mining/index.mdx:55-84`). Event `NeuronRegistered`.

### 3.2 Immunity and pruning awareness

2. Immune while `current − BlockAtRegistration < ImmunityPeriod` (default 4,096 ≈ 13.7 h); eviction only when the subnet is at `max_allowed_uids`; pruning score is emission-based regardless of role; ties evict older; owner hotkeys never pruned; immunity is a preference (lowest immune pruned if no candidates / `MinNonImmuneUids`) (`DOCS/guides/mining/index.mdx:86-112`; `DOCS/hyperparameters/immunity-period.mdx:10-14`). Emissions settle at tempo boundaries only; a pruned neuron gets nothing for the partial tempo (`DOCS/concepts/emissions.mdx:184-192`). Validators lag discovery; the immunity period is the runway (`mining/index.mdx:145-149`). With commit-reveal, on-chain score is stale by the reveal period — monitor your own service (`mining/index.mdx:151-155`).

### 3.3 Publish the endpoint (`serve_axon`)

3. `SubtensorModule.serve_axon(netuid, version: u32, ip: u128, port: u16, ip_type: u8, protocol: u8, placeholder1: u8, placeholder2: u8)` (idx 4, `Pays::No`, hotkey-signed) (`DOCS/tx/serve-axon.mdx:74-106`). Chain validation (`PAL/subnets/serving.rs:216-251, 263-303`): hotkey registered on the subnet (`HotKeyNotRegisteredInNetwork`), `ip_type ∈ {4,6}` (`InvalidIpType`), IPv4 must be `< u32::MAX` and not `0x7f000001`, IPv6 not `u128::MAX`, zero IP allowed (`InvalidIpAddress`), `port != 0` (`InvalidPort`), rate limit `current − prev.block ≥ ServingRateLimit` (default 50, first serve passes, 0 disables; `ServingRateLimitExceeded`) (`DOCS/hyperparameters/serving-rate-limit.mdx:10-12`). Stores `AxonInfo { block, version, ip, port, ip_type, protocol, placeholder1, placeholder2 }` in `Axons[netuid, hotkey]` and emits `AxonServed(netuid, hotkey)`. Pool-level rejections surface as custom codes 11 `InvalidIpAddress`, 12 `ServingRateLimitExceeded`, 13 `InvalidPort` (`DOCS/concepts/transactions.mdx:121-123`).
4. SDK defaults: `protocol = 4`, `version = 1`, `ip` parsed with `ipaddress.ip_address` → `int(address)` and `ip_type = address.version` (`SDK/intents/serving.py:44-63`). `reset_axon` = `serve_axon(version 0, ip 0, port 1, ip_type 4, protocol 4)` (`serving.py:157-187`). `serve_axon_tls` (idx 40) adds `certificate: Vec<u8>` = 1 algorithm byte + ≤64 bytes public key, stored in `NeuronCertificates`; not X.509; no chain-side TLS (`DOCS/tx/serve-axon-tls.mdx:8-29`; `PAL/subnets/serving.rs:71-76`). `serve_prometheus(netuid, version, ip, port, ip_type)` (idx 5) with the same rate limit (`DOCS/tx/serve-prometheus.mdx:8-12, 74-91`). The metagraph renders an axon as `None` when `ip == 0`, `[v6]:port` when `ip_type == 6` (`SDK/metagraph.py:563-573`).
5. IP detection conventions: v10 tried `checkip.amazonaws.com`, `curl ifconfig.me`, `ipinfo.io`, `myip.dnsomatic.com`, `ident.me`, Wikipedia `X-Client-IP` (`V10/bittensor/utils/networking.py:74-133`) with `--axon.external_ip` override (`V10/bittensor/core/axon.py:324-362`). SN2 uses `https://api4.ipify.org` with a 5 s timeout, override `--external-ip`/`BT_AXON_EXTERNAL_IP`, rejects non-global IPv4 (loopback, RFC1918, CGNAT, link-local, multicast) and IPv6 entirely, skips serving for the boot if detection fails, and re-serves only when the chain entry differs (idempotent) (`SN2/sn2-miner/src/main.rs:92-102, 169-179, 323-356`; `SN2/sn2-validator/src/validator_loop/mod.rs:719-764`; `SN2/sn2-chain/src/registration.rs:22-98`). Moving hosts: publish the new axon first, wait for traffic to drain, then stop the old one (`DOCS/guides/mining/index.mdx:128-130`).

### 3.4 Serving btauth/1 endpoints (verify / blacklist / priority)

6. Wire format (normative, `DOCS/guides/signed-requests.mdx:35-102`; implementation `SDK/http_auth.py:58-76, 157-343`): headers `X-Bittensor-Version: 1`, `X-Bittensor-Hotkey`, optional `X-Bittensor-Receiver`, `X-Bittensor-Nonce` (unix ns, decimal), `X-Bittensor-Crypto: ed25519` (omitted for sr25519), `X-Bittensor-Signature: 0x<lowercase hex>`. Signed payload = 8 `\n`-joined lines, no trailing newline: `btauth/1`, scheme, uppercase method, request target in percent-encoded wire form (path + `?query`), `sha256(body)` lowercase hex, nonce, sender ss58, receiver ss58 or `-`. sr25519 uses the `b"substrate"` signing context; ed25519 is RFC 8032. Verification order: shape → receiver (reject unbound unless `require_receiver=False`) → freshness (`max_age` 10 s past, `allowed_skew` 2 s future) → signature under the declared scheme **only** (never try-both) → replay `(hotkey, nonce)` store consulted only after signature success (`InMemoryNonceStore` retention 60 s; multi-process → Redis `SET NX EX`). Errors: `MalformedAuth`, `WrongReceiver`, `StaleRequest`, `ReplayedRequest`, `BadSignature`. Clients sign a fresh nonce per attempt; transport-level retries that resend an already-signed request are rejected as replays (`signed-requests.mdx:164-168`). Golden vectors: `//Alice` → `//Bob`, nonce `1752076800000000000`, body `{"prompt": "hello"}`, sha256 `341c5744…c3cc`, ed25519 signature pinned `0x1a6b6319…f704` (`signed-requests.mdx:252-289`). Reserved headers `X-Bittensor-Drand-Round`/`-Randomness` (`:220-224`).
7. Blacklist semantics in v11 = "authentication says who; policy decides": look the caller up in the cached metagraph by hotkey, require registered + `validator_permit` + stake floor, return 403 for verified-but-unwelcome, and key rate limiting/priority by `caller.hotkey_ss58` (`DOCS/guides/signed-requests.mdx:143-156`; `DOCS/migration.mdx:462-471`). The legacy template's defaults: reject unregistered hotkeys unless `--blacklist.allow_non_registered`, require permit only with `--blacklist.force_validator_permit`, priority = caller stake (`TPL/neurons/miner.py:65-165`; `TPL/template/utils/config.py:144-156`). ## 8. Discrepancies and open questions found while cross-checking

1. Null capacity: 2,500 (`DOCS/guides/null-consensus.mdx:43`, `SDK/hyperparams.py:319-321`) vs 16,000 (`DOCS/hyperparameters/max-allowed-uids.mdx:12`). Read the chain (`MinAllowedUids`, setter errors) rather than hardcode.
2. Take-change fees: `DOCS/concepts/transactions.mdx:161-165` lists take changes as fee-free; `DOCS/tx/set-take.mdx:72,88` show `Pays::Yes` and `DOCS/migration.mdx:569-570` says they pay. Trust the dispatch annotation.
3. `TaoWeight`: runtime default ≈5.27% (`RT:976`), docs say 0.18 on mainnet (`DOCS/guides/validating.mdx:49-52`) and "runtime default ~0.053". Always read `TaoWeight`.
4. `StakeThreshold` mainnet value is only described as "around 1,000 TAO-equivalent" (`validating.mdx:44-47`); runtime default is 0 (`PAL/lib.rs:1213-1215`). Must be read live.
5. `DOCS/cli.mdx:42-44` lists `weights`, `axon`, `sudo` as top-level groups; `SDK/cli/main.py:99-144` nests `weights`/`axon` under `misc` and names the owner group `hparams` (hidden alias `sudo`). Docs lag the code.
6. `InitialMinAllowedWeights` runtime default is 1024 (`RT:918`) — real subnets override it; the effective minimum is `min(param, SubnetworkN)`.
7. `get_max_weight_limit` is pinned to `u16::MAX` in the runtime while `MaxWeightsLimit` storage still exists and the SDK clips to it (`DOCS/hyperparameters/max-weights-limit.mdx:27-35`); rtao should clip to storage for parity but know the chain won't reject.
8. SN2 encrypts commits with the v1 `bittensor_drand::generate_commit` formula (`SN2/sn2-chain/src/weights.rs:60-82`) while the v11 core uses the stateful v2 (`CORE/timelock/mod.rs:160-200`); v2 is the one to port.
9. IPv6 axons: chain accepts `ip_type 6` (`PAL/subnets/serving.rs:216-243`) and the SDK encodes it, but SN2 rejects IPv6 (`SN2/sn2-miner/src/main.rs:347-356`). rtao should support v6 encoding but default to v4 detection.
10. `bittensor-core` is `publish = false` (`SUB/sdk/bittensor-core/Cargo.toml`), so rtao must vendor/port (not depend on) its timelock (`tle` at the ideal-lab5 rev + vendored `w3f-bls` fork), PoW, keyfile, and epoch-schedule code to stay byte-compatible with pallet-drand decryption (`Cargo.toml` comments at `SUB/sdk/bittensor-core/Cargo.toml` dependencies block).
11. `register_network_with_identity`, `Commitments.set_commitment`, `trigger_epoch`, `set_auto_parent_delegation_enabled`, `sudo_set_sn_owner_hotkey`, `sudo_set_mechanism_emission_split` have no v11 intent; rtao needs typed wrappers or a raw-call path for them.
