## Findings (most severe first)

### PP-01 [blocker] architecture.md — intent alpha amounts cannot be on netuid 0 or depend on a sibling netuid
- Location: §5.2 `impl Balance<Alpha> { pub fn new(netuid: NetUid, rao: u64) -> Result<Self, UnitError>; // netuid 0 is TAO: use Balance<Tao>` and "Intent money fields use `Amount<U>`"; §4.2 "money (`anyOf` with the decimal pattern) → `Amount<Tao>` or `Amount<Alpha>` by name suffix".
- Problem: Python's `*_alpha` fields get their netuid from a sibling field and are valid on netuid 0 (root alpha = TAO 1:1, tagged netuid 0). As specified, `Amount<Alpha>` wraps `Balance<Alpha>`, which rejects netuid 0, and serde parses the field before the sibling netuid is known. rtao cannot build `remove_stake`, `remove_stake_limit`, `move_stake`, `swap_stake`, `transfer_stake`, `move_swap_stake` on the root subnet (Python has dedicated root branches) or basket legs touching netuid 0. Three money fields have no suffix. Upstream oracle samples use netuid 1 for every staking op, so the oracle would not catch the root breakage.
- Evidence: `PY/intents/_money.py:85-90` ("on a root origin (netuid 0) alpha is TAO 1:1, so the netuid-0 tag `call_amount` derives is the right unit there too"), `:139-163` (`call_amount` accepts netuid 0); `PY/intents/staking.py:701-704` (`call_amount(..., netuid=self.netuid)`), root branches `:306, 339, 772-776, 914-916, 1102-1104`; `:1789-1793` (swap_basket amount→origin_netuid, min_amount_out→dest_netuid); `PY/intents/root.py:116-124`; CAT money properties without suffix: `swap_basket.amount`, `swap_basket.min_amount_out`, `set_root_claim_threshold.threshold`; `PYT/harness/samples.py:43-74` (all staking samples netuid 1/2), `:145-150`.
- Fix: replace the §5.2 "Intent money fields" bullet with: "Intent money fields deserialize to `Amount<Unresolved>` (number, decimal string `^\d+(\.\d+)?$`, or `"all"` for `ALL_AMOUNT_FIELDS`; exact; negatives rejected; no unit yet). The generated `validate()` resolves each with a port of `call_amount` (`PY/intents/_money.py:139-163`): unit from the wrapped call argument's type ident in the `CallDescriptor` (`TaoBalance`/`AlphaBalance`; fallback: extracted `_FALLBACK_AMOUNT_UNITS`, `:89-128`), netuid from the sibling field named in `codegen/intent_types.toml` (`amount_alpha`→`netuid`|`origin_netuid`; `swap_basket.amount`→`origin_netuid`; `swap_basket.min_amount_out`→`dest_netuid`; `swap_basket_many.legs[*]` per leg; `set_root_claim_threshold.threshold`→TAO). The result is a `DynBalance`; netuid 0 is valid and means TAO. `Balance<Alpha>` (netuid ≠ 0) stays a domain type with `TryFrom<DynBalance>`." Add to §4.2: "A money property without `_tao`/`_alpha` suffix needs an explicit override; the generator fails otherwise." Add to §11.5: "`vendor/oracle/samples_extra.json` adds netuid-0 samples for remove_stake, remove_stake_limit, move_stake, swap_stake, transfer_stake, move_swap_stake, unstake_all (with and without `claim`), dumped by the Python oracle (M5)."
