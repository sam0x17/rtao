Q25 / D-035 native balance implementation (2026-10-14)
This supersedes the earlier Q24 signed-balance implementation and evidence.

Stable source:
- Balance<Tao>, Balance<Alpha>, and DynBalance store native u64 rao.
- Typed/dynamic checked_add, checked_sub, and try_sum return Result<Self,UnitError>, reporting Overflow or Underflow; currency mismatches remain explicit and are checked even after a sum overflow.
- DynBalance.from_rao(u64,NetUid); try_from_rao(i128,NetUid) rejects negatives/oversize; try_from_unsigned_rao(u128,NetUid) rejects oversize. Exact decimal/numeric input rejects negative values, excess precision, and native overflow.
- DynBalance.amount()->f64 and to_python_string()->String are infallible within u64; tao()/alpha() remain checked typed conversions. unit() uses Cow for synthesized alpha symbols.
- No signed DynBalance compatibility, negation, arbitrary-size balance APIs, RaoOperand, or bigint balance formatter remains. General fixed-point/f64 formatting still uses BigUint internally; it is not a balance representation.
- Public DynBalance.try_into_core_value validates NetUid before passing native rao through core; typed/wire IntoCoreValue remains direct.
- Explicit saturating_sub retains its descriptive name; checked_sub never saturates.
- All original property source references annotate Q25/D-035 adaptation to 0..=u64::MAX; NETUID0..=4095/SUBNET1..=4095 remain unchanged. No full-signed-Python parity claim remains.
