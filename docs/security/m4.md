### M4-S1: unresolved post-transmission errors can discard the transaction hash

Severity: medium. Resolution: open.

**Classification:** Internal inference failure in the submission/recovery safety
contract.

**Target:** `crates/rtao-client/src/submit.rs:652,657,700` propagates block/hash,
receipt-RPC and decoding failures after author submission. Malformed watch
statuses also return ordinary protocol errors at lines 606 and 679. The exact
attempted hash exists, but `submission_timeout_error` at line 1284 promotes only
timeouts. `submit_with_lease` at line 514 reconciles only typed unknown fate or
retraction. The shield caller has the same restriction at
`crates/rtao-client/src/shield.rs:288`.

**Strongest answer in the artifact:** Disconnects, subscription loss and
timeouts retain an exact `FateUnknown` hash, invalidate leases, and can reconcile
without retransmission. The regression
`crates/rtao-client/tests/submission.rs:965`,
`full_timeout_during_report_resolution_keeps_hash_without_rebroadcast`, tests a
silent receipt RPC for all three submit entry points.

**Ownership and perspective audit:** The client owns the signed bytes and their
hash. The node may already have included them. The SDK/CLI caller receives the
error and needs the hash to decide whether another mutation is safe.

**Precise remaining failure:** Replace that fixture's silent `chain_getBlock`
reply with an immediate JSON-RPC error, or return an invalid block object after
an inclusion notification. The failure is not a timeout, so it bypasses the
promotion and reconciliation conditions. Raw/shield lifting returns an ordinary
`TxError` at `crates/rtao-tx/src/executor.rs:948`, without a result carrying
`fate_unknown`. A transaction can have executed while the caller receives no
submission identity. This does not prove an internal automatic rebroadcast; it
makes caller/manual retries unsafe and bypasses requested reconciliation.

**Proportionate remedy:** Preserve the attempted hash and original cause for
every unresolved error after transmission, including receipt/protocol errors
and reconciliation failures. Keep proven pool rejection and proven expiry
distinct. Route these unresolved outcomes through the existing reconciliation
and CLI recovery handling.

Suggested hosted regressions: immediate receipt-RPC error, malformed watch
shape/hash, receipt decode failure, and a failure during reconciliation. Cover
direct, leased, prebuilt and shield submission; assert the exact attempted hash,
one author request, correct lease invalidation and no silent success. With
reconciliation enabled, show recovery from a transient receipt error under the
original total deadline.

### M4-S2: untrusted identity text reaches the terminal as control bytes

Severity: medium. Resolution: open.

**Classification:** Internal inference failure in the human review boundary.

**Target:** `crates/rtao-cli/src/output.rs:1129` clones string cells verbatim;
`fields` and `line` write them to the terminal at lines 976 and 1071. An actual
remote-input route is `crates/rtao-reads/src/reads/owner.rs:280,867` through
`crates/rtao-cli/src/commands/hparams.rs:1043`, which renders subnet identity
fields as human detail cells. Semantic transaction review also places raw
argument strings in those cells (`crates/rtao-cli/src/context.rs:560`).

**Strongest answer in the artifact:** JSON serialization escapes control bytes.
Identity summaries use Python string repr (`crates/rtao-intents/src/identity.rs:9`)
and RPC policy diagnostics sanitize hostile text. The identity build deliberately
preserves UTF-8 bytes, including its NUL/newline fixtures, rather than rejecting
all such data.

**Ownership and perspective audit:** A subnet owner or supplied argument controls
the text; the local operator owns the terminal and confirmation decision. These
are distinct trust domains. A valid UTF-8 ESC character remains valid chain
identity data.

**Precise remaining failure:** A subnet description containing the bytes
`ESC [ 2 J ESC [ H` survives UTF-8 normalization and is emitted unchanged in
human `hparams get-identity` output. The same strings can enter review cells.
Terminal control sequences can clear or rewrite displayed information. Escaping
the summary or the JSON branch does not protect the detail/transaction-card
branch. The finding concerns display integrity, not a demonstrated key leak or
shell execution.

**Proportionate remedy:** Escape terminal controls and directional formatting
characters at the human rendering boundary, including titles, field names,
scalar values, nested repr, messages and prompts. Preserve the actual call bytes
and JSON values. Do not rely on table-library behavior: this path writes directly
to the sink.

Suggested hosted regressions: fake-chain subnet identity with ESC/OSC, BEL,
carriage return and bidi controls; assert visible escaped human output and exact
JSON round trips. Exercise a semantic transaction card and raw-call review with
the same controls, verifying that the signer/operation and confirmation remain
readable.

### M4-S3: raw-call and weights files have no acquisition limit

Severity: low. Resolution: open.

**Classification:** Internal inference failure in the input-budget boundary.

**Target:** `crates/rtao-cli/src/call.rs:511` uses
`std::fs::read_to_string` for `--args-file` before JSON parsing.
`crates/rtao-cli/src/commands/weights.rs:197` supplies the same unbounded reader
for `--weights-file`. Supporting shared config/cache acquisition also uses
unbounded `fs::read` in `crates/rtao-client/src/config.rs:552`.

**Strongest answer in the artifact:** JSON parsing and raw composition enforce
nesting limits; books and wallet readers have byte limits. The raw-call fixture
at `crates/rtao-cli/tests/raw_call_contract.rs:1330` verifies file/inline
exclusivity and normal files. Wallet tests explicitly cover sparse oversized
files and prompt FIFO refusal.

**Ownership and perspective audit:** A local operator selects the path, but
its contents or file type can come from a supplied file or producer. This is a
local availability issue, not an unauthenticated remote service vulnerability.

**Precise remaining failure:** Neither production CLI reader uses the bounded
wallet/book helper. A sparse oversized regular file is acquired before parsing
can reject it; a FIFO can block in `open` without a producer. The raw path runs
before connection or confirmation, including dry runs. A JSON recursion limit
does not limit those operations. Shared config's `is_file` check avoids a stable
FIFO but supplies no byte budget.

**Proportionate remedy:** Use bounded descriptor-based regular-file acquisition
with a nonblocking Unix open, a metadata size check, and a capped read that also
handles file growth. Apply an explicit byte limit to inline JSON and to the
shared config/cache reader. Refuse limit errors without quarantining or
overwriting the input.

Suggested hosted regressions: boundary-size, sparse oversized and growing
files, directories, FIFOs and regular symlinks under the intended symlink
policy. Exercise both real CLI entry points and config startup; assert bounded
refusal, no RPC/key acquisition, and preservation of the original input.

### M4-S4: secret output creates ordinary heap copies without erasure

Severity: low. Resolution: open.

**Classification:** Internal inference failure in the application-owned secret
zeroization boundary.

**Target:** `crates/rtao-cli/src/commands/wallet.rs:644,664` copies generated
mnemonics from `SecretString` into ordinary JSON string values, including in
human mode. JSON password export does the same at line 706. The generic output
path clones payloads (`crates/rtao-cli/src/output.rs:476,549`), serializes into an
ordinary `Vec<u8>` at line 1065, and formats human strings into ordinary buffers
at lines 1129 and 1072. `Output::mnemonic` itself creates a JSON copy at line 960.

**Strongest answer in the artifact:** The original mnemonic/password and the
human password-export buffers are guarded; printing these values is the
documented command behavior. Process capture uses zeroizing, preallocated
buffers, and the keyfile serializer counts before allocating so released growth
buffers cannot retain plaintext (`crates/rtao-core-ext/src/keyfile_json.rs:142`).

**Ownership and perspective audit:** These additional JSON/format/serialization
allocations belong to the CLI. The intended output destination is outside this
finding; the issue is the discarded application heap copies after output or an
output error.

**Precise remaining failure:** Guarding the original secret does not erase the
new `serde_json::Value::String`, cloned payload or serialized buffer. At the
locked serde_json 1.0.154 these contain ordinary `String`/`Vec` allocations, with
no secret-erasing drop. Successful rendering and sink failure both release
unwiped copies. This increases memory-residue exposure; no live memory-extraction
exploit or unintended diagnostic disclosure was demonstrated.

**Proportionate remedy:** Give intentional secret output a dedicated guarded
writer. Avoid constructing mnemonic payloads in human mode; guard and erase any
owned JSON strings and formatting buffers on all exits. Count serialized size
before writing into a zeroizing allocation, as the existing keyfile serializer
does, so growth does not leave earlier copies behind.

Suggested hosted regressions: injected success and failing sinks with disposable
secret sentinels, asserting cleanup of the owned payload/serialization guards on
both paths and one unchanged output document. Retain redacted Debug/error tests.
Do not use reads of freed allocator memory as a regression test.

### M4-S1 residual: shield polling exhaustion can conceal an unresolved outcome

Severity: medium. Resolution: open. This follow-up identified an additional
path in the original submission-safety boundary; it is not evidence that the
earlier hash-preservation repair failed on its new propagated-error fixtures.

**Classification:** Internal inference failure in the distinction between an
unresolved outcome and proven non-inclusion.

**Target:** At the follow-up snapshot,
`crates/rtao-client/src/shield.rs:420` discards errors from `chain_getBlockHash`
using `.ok().flatten()`. After the shared poll allowance reaches zero, lines
481-486 return `Ok(outer)` with `success = false` and a claim that the inner
extrinsic was not included before expiry. This exit does not reach
`submission_attempt_error`. The executor's ordinary report conversion sets
`fate_unknown` to `None` (`crates/rtao-tx/src/output.rs:128,159`).

**Strongest answer in the artifact:** The scan has a finite era-height range
and a shared allowance of four polls per era block. Missing heights can recover
within that allowance; the delayed-inner fixture tests this. The shield path
does not automatically resubmit, invalidates unsettled nonces, and the returned
carrier report retains its shield identities. The current fixture
`crates/rtao-client/tests/shield.rs:427` explicitly expects an ordinary failure
after 36 misses for height 102.

**Ownership and perspective audit:** The node controls availability of block
hashes, while chain progress determines whether the signed inner can still
execute. The client owns the receipt classification; the caller uses that
classification to decide whether retrying the mutation is safe. Elapsed polls
do not establish either canonical non-inclusion or era expiry.

**Precise remaining failure:** After carrier inclusion, let the chain stop
before the next height exists. With the default absent total deadline, 36
successful null replies exhaust the P8 allowance even though the chain has not
advanced past the inner's era. Alternatively, let the relevant block-hash RPC
repeatedly return an error while the inner was included. Both schedules reach
the same ordinary failure return: the first can still execute later, and the
second has not established absence. The new unresolved-error handler cannot
classify an error that this path discards or converts into an `Ok` report. The
returned carrier/inner identities aid manual inspection but do not repair the
false known-failure classification.

**Proportionate remedy:** Distinguish an unproduced height from a failed block
lookup. Exhausting a polling budget before proving canonical expiry and
completing the relevant scan must return an unresolved outcome with the
attempted carrier identity and available cause. Propagate block-hash failures
through the new preservation path, or retain them while making bounded read
retries. Reserve the ordinary non-inclusion result for an expiry/absence check
supported by chain state.

Suggested hosted regressions: hold the best/finalized heads before expiry while
returning null for the next height; separately return immediate RPC errors or a
malformed hash only after carrier admission. Let the poll allowance exhaust
without the outer deadline expiring first. Assert unknown fate with the exact
carrier hash, one author submission and nonce invalidation. Resume chain
progress and include the original inner to demonstrate why the earlier result
must not authorize a retry. Replace the existing unconditional expiry assertion
with separate unresolved and proven-expiry cases; inspect the executor result
as well as the client error.
