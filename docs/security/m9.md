## Open findings

### S9-01: high, unauthenticated hotkey headers cause quadratic CPU work

Locations: `crates/rtao-btauth/src/lib.rs:397`, `:432`;
`crates/rtao-neuron/src/miner.rs:206`;
`vendor/upstream/src/sdk/bittensor-core/src/keys/mod.rs:49`.

`authenticate` accepts any nonempty sender header and synchronously passes it to
SS58 verification on the request task. The pinned core delegates to sp-core's
`Ss58Codec::from_ss58check_with_version`, which base58-decodes the whole string
before checking its decoded length. Locked bs58 0.5.1's `decode_into` loops over
an expanding output for each character, giving quadratic work for a long
nonzero base58 string.

An unauthenticated peer can supply a 100 KiB `X-Bittensor-Hotkey` made of `z`, a
current nonce, the public receiver, an empty body and an arbitrary 64-byte hex
signature. Address decoding runs before the signature can fail, before caller
policy and before the limiter. Repeating such requests can occupy Tokio workers
and deny service. Both strict and wrapped verification take this decoder path.

The strongest defense was HTTP/header and body limits. The default miner uses
`axum::serve` without a smaller header budget. Locked Hyper 1.12.0's default
header buffer is 417,792 bytes (`src/proto/h1/io.rs:23`), admitting this request.
The body cap constrains no sender-header bytes. PR-U17 modifies Ledger files,
not this core key decoder. No timing experiment was performed.

Disposition: **open**. Reject oversized authentication fields before number,
signature or address decoding. A 64-byte sender ceiling accommodates the
supported SS58 account addresses; nonce/crypto/signature spellings and aggregate
authentication headers also need finite budgets.

### S9-02: high, registered nested dispatch bypasses spend and subnet policy

Locations: `crates/rtao-intents/src/multisig.rs:152`, `:409`, `:530`;
`crates/rtao-intents/src/proxy.rs:169`;
`crates/rtao-tx/src/intent.rs:290`, `:324`;
`crates/rtao-tx/src/policy.rs:24`, `:54`;
`crates/rtao-tx/src/executor.rs:392`.

`MultisigThreshold1`, `MultisigExecute` and `ExecuteProxyAnnounced` build an
arbitrary registered child call but keep the base `Spend::None`, empty subnet
set and outer semantic identity. They are not marked raw for `Policy::check`.
The executor checks those outer facts, so the child's safety contract is lost.

For a funded 1-of-N multisig account, an untrusted tool call can select
`multisig_threshold_1` with an inner `transfer` whose `amount_tao` is `"all"` and
whose destination is attacker-controlled. With a member coldkey available, the
outer operation passes `max_spend = 0` and `allow_raw_calls = false`, then
dispatches `Balances.transfer_all` from the derived account. Existing higher
threshold operations and announced proxies give analogous paths when their
chain prerequisites are satisfied. Subnet allowlists and required shield
semantics can likewise disappear inside these dispatchers.

The strongest defense was intentional Python parity and the separate semantic
multisig adapter. Tests at `multisig.rs:754` and `:1438` explicitly retain the
base defaults, but no accepted security exception authorizes policy bypass.
The adapter's stronger behavior does not protect the registered tool path.
Account/signature checks establish signing identity, not the lost policy facts.

Disposition: **open**. Either propagate and conservatively aggregate the inner
contract, or treat these opaque compositions as raw and require explicit raw
authorization. Add policy-refusal fixtures for nested transfer-all and forbidden
subnet operations, including a registered dispatcher inside a Batch.

### S9-03: medium, Batch drops mandatory child shielding

Locations: `crates/rtao-intents/src/batch.rs:188`;
`crates/rtao-catalog/src/specs.rs:450`;
`crates/rtao-tx/src/executor.rs:1006`.

Batch builds each child directly, while automatic shielding checks only the
outer semantic spec. Batch's spec has `mev_shield_required = false`. A Batch
containing `burned_register` or `add_collateral`, whose specs require shielding,
therefore follows ordinary author submission under default options. This issue
also exists with children whose spend/subnet aggregation is otherwise correct.

Both child builders were checked for equivalent protection; neither rejects
unshielded composition. AddCollateral retains its price limit, so this report
does not allege that its tolerance disappears. The defect exposes a call that
the required-shield contract promises to keep private. Python-compatible child
build behavior does not enforce that contract.

Disposition: **open**. Carry child-required shielding to the batch or refuse
composition that cannot preserve it. Verify both required-shield child cases
before claiming closure.

### S9-04: medium, queried axons can exhaust validator memory

Location: `crates/rtao-btauth/src/client.rs:339`.

Both fan-out APIs collect every successful axon response with
`response.bytes().await` before JSON decoding, without a response-byte ceiling.
A queried miner can send a large fixed-length or chunked response and make the
validator retain it until completion or timeout. Default concurrency is 256;
JSON decoding adds further allocations after collection.

The strongest defense was the attempt/call deadlines. They constrain elapsed
time, not bytes arriving within it. Locked reqwest's collection supplies no
hidden body cap. The lower-level streaming request API allows caller-controlled
consumption, but fan-out gives callers no interception point before collection.

Disposition: **open**. Add a finite configurable response budget, reject
oversized declared lengths and enforce the same budget while consuming chunks.

### S9-05: medium, unsolicited RPC notifications have no retained-byte budget

Locations: `crates/rtao-rpc/src/session.rs:1227`;
`crates/rtao-rpc/src/session.rs:1548`;
`crates/rtao-rpc/src/types.rs:273`;
`crates/rtao-rpc/src/generated/py_rpc.rs:27`.

Unknown subscription IDs enter the early-notification buffers even when no
subscription establishment is outstanding. Retention is bounded by entry count
and ID count, without a byte budget. Defaults permit 2,048 values per ID, 64 IDs
and 256 MiB per message. One unknown ID receiving 16 MiB values can retain about
32 GiB while every message satisfies the transport limit.

Count caps and the silence timeout were checked as defenses. The caps permit
this allocation; ongoing frames reset the silence timer. TLS authenticates the
configured endpoint but cannot make a compromised or hostile endpoint's
notifications safe. Read-only client use can reach this path.

Disposition: **open**. Bound aggregate retained bytes in early and active
subscription queues, and buffer early notifications only while a relevant
subscription request is pending.

### S9-06: medium, cancelled key replacement loses serialization

Locations: `crates/rtao-wallet/src/files.rs:218`, `:251`, `:278`;
`crates/rtao-wallet/src/messages.rs:97`.

`FileState::store` holds the cache mutex in the async caller while a blocking
worker encrypts and installs the key. Cancelling that caller drops its mutex
guard, while an already-started worker continues. A second unlock can cache the
old key before the worker installs its replacement; cancellation skips the
final invalidation, leaving that old signer available afterward. Message signing
uses this cache directly. A later replacement can also run concurrently and
finish before the cancelled earlier worker, which may then overwrite it.

Atomic owner-only writes protect each publication, but they do not retain the
operation lock after caller cancellation. The executor's account comparison
mitigates mismatched transaction signing, so unauthorized transaction submission
is not asserted. The remaining impact is stale signing identity and keyfile
state that can disagree with a later completed replacement.

Disposition: **open**. Keep serialization and final invalidation owned by work
that survives cancellation. A deterministic paused-worker regression should
cover cancellation, concurrent unlock and two replacements finishing out of order.

### S9-07: low, secret-reader growth frees unwiped earlier allocations

Location: `crates/rtao-wallet/src/files.rs:509`.

The bounded reader puts an empty Vec in `Zeroizing`, then grows it through
`read_to_end`. Growth can release an earlier allocation containing a plaintext
keyfile or password prefix before the final owner's drop can wipe it. The
inspected Rust 1.89 `Take<File>` implementation uses the default growing reader.
The final guard and the 16 MiB limit do not erase retired allocations.

This requires a separate memory-disclosure capability and is already documented
as excluded from the earlier parser repair in `docs/security/m2.md:218`.
No direct log or remote-disclosure path is asserted.

Disposition: **open, previously documented**. Use a bounded acquisition strategy
that prevents secret-bearing reallocations or wipes retired storage on growth.
Do not describe the current reader as erasing every copy.

### S9-08: low, verbose raw RPC logs permit terminal control injection

Locations: `crates/rtao-rpc/src/session.rs:943`;
`crates/rtao-cli/src/logs.rs:195`, `:215`.

Before JSON validation, text frames are logged as `frame=%raw`. With `-vvv` or
`BITTENSOR_LOG=trace`, the CLI formats this named field and writes its bytes to
stderr. Locked tracing-subscriber 0.3.23 sanitizes the `message` field but formats
other named fields directly. A malformed JSON text frame can thus
carry ESC/OSC terminal sequences into the operator's terminal.

The ordinary human-output renderer escapes controls, and verbose raw logs are
opt-in. Neither protects this diagnostic path; `with_ansi(false)` only disables
formatter-generated color. The impact depends on terminal behavior and can
include misleading output or clipboard control. No terminal payload ran.

Disposition: **open**. Escape control characters for diagnostic frame output
while retaining the original bytes for protocol parsing.

### S9-09: low, persisted-data loaders accept unbounded or blocking files

Locations: `crates/rtao-metagraph/src/persist.rs:244`;
`crates/rtao-neuron/src/state.rs:290`, `:392`;
`crates/rtao-client/src/cache.rs:655`.

Metagraph loading, neuron checkpoint loading and live metadata-cache loading
use unbounded filesystem reads without descriptor-level regular-file checks.
A supplied oversized metagraph/checkpoint/cache file can exhaust memory before
format or identity validation. A FIFO at an expected path can hold a blocking
worker indefinitely. Checkpoint generation rotation also opens and copies its
source without a bound or regular-file check.

The strongest defenses were format validation and blocking-worker offload.
Validation happens after acquisition; offload protects the reactor but does not
bound memory or stop a stuck worker. Metadata's separate offline-cache path has
a regular-file check and 64 MiB bounded read, but the live `load_disk` path does
not use it. The attack requires local file placement or explicit use of an
untrusted persisted file; no remote arbitrary-path write is asserted.

Disposition: **open**. Apply descriptor-based regular-file and size checks,
bounded reads/copies and nonblocking special-file refusal to these loaders.

### Supplemental S9-10: high, retained multisig bytes lack semantic provenance

Independent follow-up review found that the CLI adapter, and the initially
authored public typed adapters, accepted arbitrary runtime-stamped pinned bytes
alongside an unrelated semantic intent. The executor skips semantic rebuilding
for such bytes. A zero-spend label could therefore authorize a transfer-all
call under a spend cap; subnet and mandatory-shield requirements could also be
misrepresented. A runtime stamp establishes the metadata revision, not the
relationship between a call and its safety contract.

The CLI repair now carries an opaque continuation bound to semantic JSON,
canonical multisig account and effective dispatch origin. Its implementation
module is crate-private: a public wrap hook must not mint a purported review
proof from arbitrary bytes. The controller retains exact bytes across rounds;
authored fixtures obtain a real proof before trying an operation/argument or
account substitution. A second source reread found no remaining issue in this
CLI correction. Public generic adapters use a separate executor-review proof
path. Independent review found that continuation origin resolution used a static
catalog signer after selecting a dynamic role. The correction binds
IntentKeyView to that dynamic role; real hotkey-Batch fixtures cover both
thresholds and exact retained bytes in the typed adapters and CLI. Final reread
by `/root/axon_cap_review` on 2026-10-15 found no surviving defect in the dynamic
role binding, proof provenance, semantic/group binding, runtime checks or
effective-origin refusal. Hosted execution remains pending.

combined hosted regressions and committed-source linkage before claiming
