| Boundary | Reviewed behavior and evidence |
|---|---|
| Freshness and retention | [Verifier construction](../../crates/rtao-btauth/src/lib.rs#L367) requires `retention > max_age + allowed_skew`, using checked duration addition. [Freshness](../../crates/rtao-btauth/src/lib.rs#L452) accepts both endpoints of the interval. At the defaults, a nonce can be fresh for 12 seconds from its earliest permitted arrival; retention must exceed that interval because memory expiry occurs at `elapsed >= retention`. The [conformance regression](../../crates/rtao-btauth/tests/conformance.rs#L944) rejects equality and one nanosecond below, and accepts one nanosecond above. |
| Signature inputs | [Authentication](../../crates/rtao-btauth/src/lib.rs#L383) checks version and field syntax, receiver binding, freshness and the declared algorithm before returning an authenticated token. The payload binds protocol, algorithm, uppercase method, raw target, SHA-256 of raw body bytes, canonical integer nonce, sender and receiver. Sender addresses normalize to an `AccountId` only after verification, so alternate SS58 spellings share replay identity. |
| Admission order | The [Tower path](../../crates/rtao-btauth/src/server.rs#L406) authenticates, applies policy, commits replay state, then applies the limiter. Invalid signatures and policy denials cannot fill replay storage. Replays cannot consume limiter tokens. A fresh request rejected by the limiter has already committed its nonce and must be retried with a fresh signature. |
| Awaited work | [Freshness is rechecked](../../crates/rtao-btauth/src/server.rs#L418) after policy work and after replay-store I/O, before handler admission. [Policy-delay](../../crates/rtao-btauth/tests/server.rs#L520) and [store-delay](../../crates/rtao-btauth/tests/server.rs#L578) tests exercise those boundaries. |
| Verification clock | The [default clock](../../crates/rtao-btauth/src/server.rs#L296) takes the maximum of Unix time and its previous Unix anchor advanced by monotonic elapsed time. Backward wall-clock changes cannot reopen freshness while memory-store retention continues to expire. Custom clocks must advance at least as fast as store expiry, as the API documents. |
| Replay storage | [Memory insertion](../../crates/rtao-btauth/src/nonce.rs#L285) checks and inserts under one hotkey shard lock, with an atomic global reservation. Duplicates do not allocate queue entries or extend retention. Capacity errors preserve live entries. [Expiry](../../crates/rtao-btauth/src/nonce.rs#L224) uses monotonic insertion time, clamps backward samples and releases expired allocations. Poisoned locks fail closed. |
| Body bounds | [The layer](../../crates/rtao-btauth/src/server.rs#L372) rejects a declared oversize length without polling the body and wraps unknown-length bodies in `Limited` before collection. The pinned `http-body-util` 0.1.5 implementation checks each data frame before yielding it to the collector. [Stream-poll assertions](../../crates/rtao-btauth/tests/server.rs#L383) verify early refusal; a [signed 3 MiB JSON request](../../crates/rtao-btauth/tests/server.rs#L342) reaches the handler with matching router limits. |
| Nested request targets | [Target selection](../../crates/rtao-btauth/src/server.rs#L401) uses axum `OriginalUri` when present and preserves raw path/query encoding, query order and an empty query. The [nested-router regression](../../crates/rtao-btauth/tests/server.rs#L464) accepts the original signed outer path and rejects a signature for the stripped inner path. HTTP peers cannot populate request extensions directly. |
| Policy identity | [Metagraph admission](../../crates/rtao-btauth/src/server.rs#L96) reads one snapshot, checks membership and permit when required, and compares exact stake weights. Unavailable stake fails admission. Only the verified caller becomes the handler's `Caller` extension. |
| Limiter bounds | [The limiter](../../crates/rtao-btauth/src/server.rs#L195) rejects zero quotas, serializes integer token accounting and bounds remembered hotkeys. It removes only fully replenished buckets, which are equivalent to absent state. Outstanding debt is retained at capacity. Concurrent tests cover token and slot limits; full/poisoned state returns 503 and token exhaustion returns 429 with rounded-up `Retry-After`. |
| Redis atomicity | [The Redis adapter](../../crates/rtao-btauth/src/redis.rs#L59) verifies positive `maxmemory` and `noeviction`, then sends one `SET key 1 NX PX ttl` operation per attempt. It preserves signed integer nonce identity, does not refresh duplicates, does not delete keys and does not retry ambiguous outcomes. OOM returns `Full`; other errors and timeouts close all clones to further operations. Backend details and credentials are suppressed. |
| Redis TTL | [TTL conversion](../../crates/rtao-btauth/src/redis.rs#L136) uses `ceil(retention_ns / 1_000_000) + 1` milliseconds and rejects zero or out-of-range values. This covers millisecond expiry rounding. It does not make Redis expiry monotonic or guarantee persistence; those deployment conditions are stated below. |
| Legacy v10 | [The optional bridge](../../crates/rtao-btauth/src/legacy.rs#L1) verifies the documented dotted sr25519 signature using an application-supplied schema body hash. It explicitly requires the application to enforce receiver identity, freshness and replay protection, and does not claim method or target binding. It is not an automatic fallback in `BtAuthLayer`. |

The operational contract remains material. Memory replay state protects one
shared store instance and is lost on process restart; separate worker
processes need a shared backend. The outer body cap and the inner router's
`DefaultBodyLimit` must match. A byte cap does not establish connection,
concurrency or slow-body time limits for the surrounding HTTP deployment.
The v10 bridge requires the application checks described above.

Redis must remain a dedicated, trusted, bounded, non-evicting deployment with
protected live keys and preserved state across restart and failover. Application
credentials must not mutate configuration or expiry. Redis documents that
[expiry uses absolute Unix timestamps and is sensitive to server-clock steps](https://redis.io/docs/latest/commands/expire/#expires-and-persistence).
Stable Redis timekeeping is therefore part of preserving replay state; the
server's local monotonic clock cannot compensate for early Redis expiry.
The adapter already requires admission to stop after any replay-state loss
for at least the configured retention before constructing a new store.
The RESP fixture uses `Instant` and is evidence about client commands, return
handling and atomic fixture behavior. It does not validate actual Redis clock,
memory, persistence, ACL, cluster or failover behavior. The official
[SET contract](https://redis.io/docs/latest/commands/set/) was checked for
`NX`/`PX` semantics during this review. No live Redis or hosted interop run is
claimed here.
